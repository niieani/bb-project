# M4 — BB-krezgwel

Integrate Swift tests/app artifact into the existing release, signing, notarization, and Homebrew path. Test configuration/artifact behavior; verify local and real-machine path where available; full gates; fp report/commit/assignment.

## Design

- Preserve GoReleaser's existing Linux job and standalone `bb` signing path.
- Add one dependent `macos-26` job to the same reusable workflow because Swift 6.2 release builds, Developer ID keychain signing, `notarytool`, and ticket stapling require current macOS/Xcode.
- Reuse the exact existing Apple 1Password items and load the Homebrew token from the same vault. `OP_SERVICE_ACCOUNT_TOKEN` remains the only GitHub-managed release secret.
- Publish a dedicated `BBMenuBar_<version>_macOS.zip` and `bb-menubar` cask. This keeps GoReleaser's architecture-specific CLI archives intact while making app install/upgrade routine through the same tap.
- Package/sign/notarize and cask generation live in testable scripts; workflow YAML only coordinates jobs and credentials.

## Verification

- `script/test_release_macos_app.sh`: cask syntax/content and workflow credential/path contract.
- `script/package_macos_app.sh --version 0.0.0 ...`: Swift tests, release build, bundle metadata, deterministic ZIP shape without release credentials.
- `actionlint`: workflow syntax and expression validation.
- Tagged workflow: notarization Accepted, stapler validation, release asset, tap update, real Homebrew install/upgrade, Gatekeeper assessment.
